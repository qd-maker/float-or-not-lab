# Gate3 AI 协作挑战每日进度记录

项目名称：浮不浮实验室 Float or Not Lab  
项目方向：初中物理浮力科普小工具  
周期：Day1 到 Day4  
仓库：`qd-maker/float-or-not-lab`

## 项目目标

做一个网页小工具，让小学高年级和初中生通过输入「物体重量」和「排开水重量」，观察物体上浮、悬浮或下沉，从而理解：

> 物体能不能浮起来，不是只看它重不重，而是看浮力能不能托住它。

## Day1

### 1. 今天完成了什么

- 确定选题：初中物理浮力，主题是「物体为什么会浮起来」。
- 确定项目名：浮不浮实验室。
- 明确只讲一个核心知识点：浮力大小近似等于物体排开水的重量。
- 明确学生用完后要理解：浮力够大就能浮，浮力不够就会沉。
- 设计了核心交互：输入物体重量和排开水重量，判断上浮、悬浮、下沉。
- 写了 API Contract，先定义请求、响应和错误码，再写后端代码。
- 搭建了 FastAPI 后端最小骨架，包含健康检查和浮力计算接口。
- 搭建了 React + Vite 前端最小骨架，包含输入区、水槽实验区、结果解释区。
- 做出了第一版可运行网页 demo，有水槽动画、浮力箭头、重力箭头和预设实验。
- 建立了 GitHub 仓库文档结构，方便后面每天更新进度。
- Day1 复盘后发现，只做两个输入判断浮沉会偏单调，所以把后续计划调整为「概念演示 + 公式计算 + 真实题目训练」。

### 2. 今天最大的困难是什么

最大的困难是避免把它做成一个普通计算器。

如果只是输入两个数字，然后输出「上浮」或「下沉」，学生可能知道结果，但不一定理解为什么。因此今天重点把概念变成画面：

- 向上的箭头表示浮力。
- 向下的箭头表示重力。
- 箭头越长，说明这个力越大。
- 物体会根据结果在水槽里上浮、悬浮或下沉。

后面复盘时又发现另一个问题：初中浮力不只是判断浮不浮，还会学阿基米德原理、称重法、漂浮平衡和真实应用题。所以 Day1 的 demo 可以作为概念演示区，但后面还需要补公式计算和题目训练。

- 帮我规划了 Day1 到 Day4 的开发节奏。
- 帮我设计了 API Contract，包括请求、响应、错误码。
- 帮我生成了 FastAPI 和 React 的初始代码结构。
- 帮我实现了第一版水槽动画、浮力箭头和重力箭头。
- 帮我把每日反馈整理成适合提交到 GitHub 的文档。
- 在复盘时帮我把后续方向调整成公式计算和真实题目训练。

### 4. AI 哪里出错了，你怎么修正的

AI 一开始有两个方向上的问题。

第一个问题是容易把项目想复杂，例如加入液体种类、完整物理引擎、复杂动画等。

我先修正为：

- Day1 只保留两个输入：物体重量、排开水重量。
- 只输出三个结果：上浮、悬浮、下沉。
- 不做复杂物理仿真，先用规则计算和动画表达概念。

第二个问题是 Day1 demo 又显得有点单调，只判断浮不浮，不够贴近初中真实学习。初中浮力还会学阿基米德原理、称重法、漂浮平衡和真实应用题。

所以我把后续计划修正为：

```text
概念演示 + 公式计算 + 真实题目训练
```

这样既不偏离「单一知识点」，又能让学生真正掌握浮力相关题型。

## Day2

### 1. 今天完成了什么

- 把 Day1 的「概念演示区」保留下来，继续用于展示上浮、悬浮、下沉。
- 新增了「公式实验室」模块，让学生不只是看动画，还能练基础浮力计算。
- 后端新增公式计算接口：`POST /api/buoyancy/formula/calculate`。
- 实现了三种初中常见浮力计算模式：
  - 阿基米德原理：`F浮 = ρ液 g V排`。
  - 称重法：`F浮 = G物 - F示`。
  - 漂浮平衡：漂浮时 `F浮 = G物`。
- 每种公式都会返回公式、代入过程、最终结果和一句学生能听懂的解释。
- 前端新增公式选择按钮、公式输入区和分步解析区。
- 对称重法做了校验：弹簧测力计示数不能大于物体在空气中的重力。
- 补充了后端测试用例，覆盖三种公式和错误输入。

### 2. 今天最大的困难是什么

今天最大的困难是把公式计算做得像「教学过程」，而不是普通计算器。

如果页面只输出一个数字，比如 `30 N`，学生可能还是不知道这个结果怎么来的。所以我把每次计算都拆成三步：

1. 先显示使用哪个公式。
2. 再显示数字如何代入。
3. 最后显示计算结果和一句解释。

这样学生能看到完整推导过程，更接近真实做题。

### 3. AI 帮了什么

- 帮我设计了公式计算接口的请求和响应结构。
- 帮我把三种公式拆成后端服务函数。
- 帮我生成了 Pydantic 校验规则。
- 帮我写了前端公式实验室的交互结构。
- 帮我补充了测试用例，包括正常计算和错误输入。
- 帮我把 Day2 的产出整理成每日五问记录。

### 4. AI 哪里出错了，你怎么修正的

AI 一开始容易把公式计算写成单纯返回结果，没有强调「代入过程」。

我修正为接口必须返回 `steps` 字段，例如：

```text
F浮 = ρ液 g V排
F浮 = 1000 × 10 × 0.003
F浮 = 30 N
```

另外，AI 一开始没有特别处理称重法里的异常情况。比如弹簧测力计示数如果大于物体重力，在这个初中题目语境下是不合理的。我补充了后端校验和前端错误提示。

- 每道题都提供分步解析和错因提示。

## Day3

### 1. 今天完成了什么

- 新增了「真实题目训练区」，放在概念实验区和公式实验室后面。
- 内置 10 道初中浮力题，覆盖判断浮沉、称重法、阿基米德公式、漂浮平衡和生活应用。
- 后端新增题库接口：`GET /api/practice/questions`。
- 后端新增判题接口：`POST /api/practice/submit`。
- 每道题提交后会显示正误、标准答案、分步解析和错因提示。
- 答错时新增「让 AI 再讲一遍」按钮。
- 新增「AI 小老师」自由提问框，可以围绕当前题或其它物理题继续问。
- 后端新增 AI 错因解释接口：`POST /api/ai/explain-mistake`。
- 后端新增 AI 自由提问接口：`POST /api/ai/ask`。
- 后端新增 AI 流式提问接口：`POST /api/ai/ask/stream`，长答案会逐段显示。
- AI 功能做成可选增强：有 `OPENAI_API_KEY` 才调用 OpenAI；没有 key 时自动返回本地模板解释，demo 不会中断。
- 优化了题目训练交互：提交后主按钮变成「已提交，先看下方解析」，解析底部再进入下一题。
- 优化了选择题选项样式，让 A/B/C 更像单选按钮，减少被误认为输入框的感觉。
- 优化了左侧题目导航，只显示题型编号和简短题干，降低信息密度。
- 给 AI 小老师增加了动态快捷追问，答错后会出现更贴近当前错误的问题。
- 前端也保留本地题库和本地判题降级，后端没启动时仍能演示基本流程。
- 更新了 API Contract，补充了 Day3 题目训练和 AI 错因解释接口。

### 2. 今天最大的困难是什么

最大的困难是控制 AI 的边界。

如果直接做成聊天框，学生可能问到浮力以外的内容，也会让项目变成「通用聊天机器人」，不符合这次只讲一个知识点的要求。所以我先把 AI 限制在答错后解释当前题，后面又调整为可提问的「AI 小老师」，但接口和 Prompt 都限制为只回答物理题目、物理概念、物理计算和物理实验现象相关内容。

另一个困难是题目训练不能只是刷题，要让学生知道为什么错。因此每题都保留标准分步解析，AI 只是补充说明，不替代标准答案。后面又发现固定错因提示不够精准，所以补了硬编码动态错因判断，例如漏乘 `g`、把测力计示数当浮力、漂浮时误以为浮力大于重力等。

### 3. AI 帮了什么

- 帮我把 Day3 功能拆成题库、判题、解析、AI 错因解释四部分。
- 帮我设计了接口字段和返回结构。

- 帮我把题目按五类题型组织起来。
- 帮我写了前后端联调代码和本地降级逻辑。
- 帮我补充了测试用例，覆盖正确答案、错误答案、无效题目、动态错因和无 AI key 的情况。
- 帮我根据体验反馈优化了 UI 状态流转，例如提交后不再一直显示「提交答案」。

### 4. AI 哪里出错了，你怎么修正的

AI 一开始容易把功能设计成开放聊天，范围太大。我先修正为「AI 小老师只在答错后解释当前题」。后面为了满足真实提问需求，又加入自由输入框，但在后端 Prompt 里限制为只回答物理题、物理概念、物理计算和物理实验现象相关内容，不做通用聊天。

AI 生成题目时也有可能出现题目超纲或解析跳步的问题。我把题目范围压回初中基础浮力，只保留判断浮沉、称重法、阿基米德公式、漂浮平衡和生活应用，并给每题补了固定分步解析。

另外，AI 接口如果强依赖真实 key，现场 demo 容易失败。我增加了后端本地模板解释和前端本地判题降级，没有 API key 时仍然能完整演示。流式接口也做了同样降级，避免没有 key 时页面卡死。
