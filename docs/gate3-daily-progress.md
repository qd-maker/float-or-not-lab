# Gate3 AI 协作挑战每日进度记录

项目名称：浮不浮实验室 Float or Not Lab  
项目方向：初中物理浮力科普小工具  
周期：Day1 到 Day4  
仓库：`qd-maker/float-or-not-lab`

## 项目目标

做一个网页小工具，让小学高年级和初中生通过输入「物体重量」和「排开水重量」，观察物体上浮、悬浮或下沉，从而理解：

> 物体能不能浮起来，不是只看它重不重，而是看浮力能不能托住它。

---

## Day1

### 1. 今天完成了什么

- 确定选题：初中物理浮力，主题是「物体为什么会浮起来」。
- 确定项目名：浮不浮实验室。
- 明确只讲一个核心知识点：浮力大小近似等于物体排开水的重量。
- 明确学生用完后要理解：浮力够大就能浮，浮力不够就会沉。
- 设计了核心交互：输入物体重量和排开水重量，判断上浮、悬浮、下沉。
- 写了 API Contract，先定义请求、响应和错误码，再写后端代码。
- 搭建了 FastAPI 后端最小骨架，包含健康检查和浮力计算接口。
- 搭建了 React + Vite 前端最小骨架，包含输入区、水槽实验区、结果解释区。
- 做出了第一版可运行网页 demo，有水槽动画、浮力箭头、重力箭头和预设实验。
- 建立了 GitHub 仓库文档结构，方便后面每天更新进度。
- Day1 复盘后发现，只做两个输入判断浮沉会偏单调，所以把后续计划调整为「概念演示 + 公式计算 + 真实题目训练」。

### 2. 今天最大的困难是什么

最大的困难是避免把它做成一个普通计算器。

如果只是输入两个数字，然后输出「上浮」或「下沉」，学生可能知道结果，但不一定理解为什么。因此今天重点把概念变成画面：

- 向上的箭头表示浮力。
- 向下的箭头表示重力。
- 箭头越长，说明这个力越大。
- 物体会根据结果在水槽里上浮、悬浮或下沉。

后面复盘时又发现另一个问题：初中浮力不只是判断浮不浮，还会学阿基米德原理、称重法、漂浮平衡和真实应用题。所以 Day1 的 demo 可以作为概念演示区，但后面还需要补公式计算和题目训练。

### 4. AI 哪里出错了，你怎么修正的

AI 一开始有两个方向上的问题。

第一个问题是容易把项目想复杂，例如加入液体种类、完整物理引擎、复杂动画等。

我先修正为：

- Day1 只保留两个输入：物体重量、排开水重量。
- 只输出三个结果：上浮、悬浮、下沉。
- 不做复杂物理仿真，先用规则计算和动画表达概念。

第二个问题是 Day1 demo 又显得有点单调，只判断浮不浮，不够贴近初中真实学习。初中浮力还会学阿基米德原理、称重法、漂浮平衡和真实应用题。

所以我把后续计划修正为：

```text
概念演示 + 公式计算 + 真实题目训练
```

这样既不偏离「单一知识点」，又能让学生真正掌握浮力相关题型。
