# 四天开发计划：浮不浮实验室

项目名称：浮不浮实验室 Float or Not Lab
项目方向：初中物理浮力科普小工具
周期：Day1 到 Day4

## 项目目标

做一个网页小工具，让小学高年级和初中生通过「概念演示、公式计算、真实题目训练」理解浮力。

核心知识点只围绕浮力展开：

> 物体能不能浮起来，不是只看它重不重，而是看它受到的浮力能不能托住它。

## 四天总体路线

| 天数 | 阶段目标 | 当天主要产出 |
| --- | --- | --- |
| Day1 | 定方向 + 搭骨架 | 确定选题、学习目标、API Contract、前后端项目骨架、第一版概念 demo、每日进度文档 |
| Day2 | 公式实验室 | 加入阿基米德公式、称重法、漂浮平衡，输出分步计算过程 |
| Day3 | 真实题目训练 + AI 错因解释 | 加入初中浮力题库、答题判断、分步解析、AI 小老师错因解释 |
| Day4 | AI 功能收口 + 部署总结 | AI 可选开关、Docker 部署、README 完善、线上 demo、演示话术、四天总结 |

## Day1：定方向 + 搭骨架

### 目标

先做出一个能跑起来的最小原型，验证这个选题能不能做成可交互网页工具。

### 计划完成

- 确定知识点：初中物理浮力。
- 确定项目名：浮不浮实验室。
- 明确目标用户：小学高年级和初中生。
- 明确核心学习目标：理解浮力能不能托住物体。
- 写 API Contract。
- 搭建 FastAPI 后端骨架。
- 搭建 React + Vite 前端骨架。
- 实现第一版输入和判断：上浮、悬浮、下沉。
- 做第一版水槽动画和浮力 / 重力箭头。
- 建立 GitHub 仓库和每日进度文档。

### 验收标准

- 本地能启动前端页面。
- 后端有健康检查接口。
- 后端有浮沉判断接口。
- 页面能输入物体重量和排开水重量。
- 每日进度文档能给老板查看。

---

## Day2：公式实验室

### 目标

把项目从「看懂浮不浮」升级成「会算基础浮力题」。

### 计划完成

- 新增公式实验室模块。
- 支持阿基米德原理计算：`F浮 = ρ液 g V排`。
- 支持称重法计算：`F浮 = G物 - F示`。
- 支持漂浮平衡解释：漂浮时 `F浮 = G物`。
- 每种计算都展示：
  - 使用公式。
  - 代入过程。
  - 最终结果。
  - 一句学生能听懂的解释。
- 后端新增公式计算接口。
- 前端新增公式输入区。
- 补充后端测试。
- 更新 Day2 每日进度。

### 验收标准

- 学生输入密度、排开体积、g 后能算出浮力。
- 学生输入空气中重力和测力计示数后能用称重法求浮力。
- 页面不是只给答案，而是显示分步计算过程。

## Day3：真实题目训练 + AI 错因解释

### 目标

让学生通过真实初中题型巩固浮力知识点，并在答错时得到更口语化的 AI 小老师解释。

AI 只做辅助解释，不做开放式聊天机器人。范围必须限制在：

```text
浮力概念、阿基米德原理、称重法、漂浮平衡、初中基础浮沉判断
```

### 计划完成

- 建立初中浮力题库。
- 至少覆盖五类题型：
  - 直接判断浮沉。
  - 称重法求浮力。
  - 阿基米德公式计算。
  - 漂浮问题。
  - 生活应用题，例如轮船、潜水艇、盐水浮鸡蛋。
- 前端增加题目训练区。
- 支持选择题或填空题提交。
- 提交后显示正误。
- 显示正确答案。
- 显示标准分步解析。
- 显示常见错因提示。
- 增加「让 AI 再讲一遍」按钮。
- 后端增加 AI 错因解释接口，输入题目、标准答案、学生答案和知识范围。
- AI 输出限制为：
  - 一句错因解释。
  - 一个解题提示。
  - 一个下一步建议。
- 如果没有 AI API Key，页面仍然显示标准解析，不影响 demo。
- 更新 Day3 每日进度。

### AI 接口草案

```http
POST /api/ai/explain-mistake
```

请求示例：

```json
{
  "question": "一个物体在空气中重 12 N，浸没在水中时弹簧测力计示数为 7 N，物体受到的浮力是多少？",
  "standard_answer": "5 N",
  "student_answer": "7 N",
  "knowledge_scope": "只允许解释浮力、阿基米德原理、称重法、漂浮平衡"
}
```

响应示例：

```json
{
  "short_explanation": "你把水中测力计示数当成了浮力，其实浮力是前后两次数值的差。",
  "hint": "称重法先找 G物 和 F示，再用 F浮 = G物 - F示。",
  "next_step": "再试一题称重法，先圈出空气中的重力和水中的示数。"
}
```

### 验收标准

- 至少有 8 到 10 道可练习题。
- 每道题都有标准解析。
- 答错时能看到错因提示。
- AI 解释只围绕当前题目和浮力知识点，不扩展成开放聊天。
- 没有 AI Key 时，题目训练仍然可用。
- 题目范围不超出初中浮力基础内容。

## Day4：AI 功能收口 + 部署和总结

### 目标

把项目整理成可演示、可部署、可写进简历的 MVP，并确保 AI 功能是可控、可关闭、不影响基础 demo 的增强项。

### 计划完成

- 完善 Dockerfile 和 docker-compose.yml。
- 整理环境变量配置。
- 增加 AI 相关环境变量：

```text
OPENAI_API_KEY=
ENABLE_AI_TUTOR=true
```

- AI 功能做降级处理：
  - 有 API Key：显示 AI 小老师错因解释。
  - 没有 API Key：显示标准解析和固定错因提示。
- 部署到服务器。
- 完善 README：
  - 项目介绍。
  - 功能说明。
  - 本地运行方法。
  - Docker 运行方法。
  - API 说明。
  - AI 小老师功能说明。
  - 环境变量配置。
- 整理四天每日进度文档。
- 准备演示流程：
  - 先演示概念实验。
  - 再演示公式计算。
  - 然后演示题目训练。
  - 最后演示答错后 AI 小老师解释。
- 整理项目取舍：为什么不做完整课程，为什么不做复杂物理引擎，为什么 AI 不做开放聊天，只做错因解释。

### 验收标准

- 项目可以通过网页访问。
- README 能让别人跑起来。
- GitHub 有连续提交记录。
- 每天都有五问进度反馈。
- 基础功能不依赖 AI Key。
- AI 解释不会超出浮力知识点范围。
- 最终 demo 能清楚讲明白浮力这个知识点。
