# 产品计划：浮不浮实验室

## 一句话介绍

一个网页实验室，让初中生通过输入「物体重量」和「排开水重量」，观察物体上浮、悬浮或下沉，理解浮力能不能托住物体。

## 为什么选这个知识点

浮力是初中物理里很适合做成交互工具的知识点。它有明确的输入、明确的结果，也可以用水槽、物体、箭头动画表现出来。

本项目不做完整浮力课程，只讲最核心的一件事：

> 浮力大小近似等于物体排开水的重量。

## 用户能学会什么

学生用完后，至少能理解：

1. 物体在水中会受到一个向上的力，这个力叫浮力。
2. 浮力够大，物体就会上浮。
3. 浮力不够，物体就会下沉。
4. 船能浮起来，不是因为它轻，而是因为它排开了很多水，获得了足够大的浮力。

## MVP 功能

### Day1

- 确定选题和学习目标。
- 完成 API Contract。
- 建立前后端项目骨架。
- 建立每日进度文档。

### Day2

- 实现前后端联调。
- 完成上浮、悬浮、下沉判断。
- 做第一版水槽动画。
- 展示浮力和重力箭头。

### Day3

- 增加石头、木块、船、潜水艇预设例子。
- 增加小测验。
- 增加 AI 小老师解释功能，限制只解释当前知识点。
- 可选接入数据库记录实验次数。

### Day4

- Docker 化。
- 部署到服务器。
- 完成 README 和演示说明。
- 整理项目总结。

## 交互设计

用户看到一个实验台页面：

1. 输入物体重量。
2. 输入排开水的重量。
3. 点击「开始实验」。
4. 水槽里的物体根据结果移动。
5. 页面显示一句解释。
6. 箭头展示浮力和重力哪个更大。

## 技术取舍

### 为什么不直接用真实物理引擎

这个项目目标是让学生理解一个知识点，不是做真实物理仿真。完整物理引擎会增加开发成本，也可能让注意力从概念理解转移到动画效果上。

所以 MVP 使用规则计算 + CSS / SVG 动画。

### 为什么先不做复杂 AI

AI 解释如果不限制范围，容易扩展到密度、体积、压强等内容。Day1 和 Day2 先把核心实验跑通，Day3 再加入受控的 AI 小老师。

### 为什么保留后端

即使核心计算前端也能完成，后端仍然有价值：

- 练习完整前后端工程结构。
- 后续可以接入数据库记录实验。
- 后续可以接入 AI 工具调用。
- 更适合部署和简历展示。
