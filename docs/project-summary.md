# Day4 项目总结

项目名称：浮不浮实验室 Float or Not Lab

## 1. 项目一句话

一个面向小学高年级和初中生的浮力科普网页工具，用概念实验、公式计算、真实题目训练和 AI 小老师，帮助学生理解「物体为什么会浮起来」。

## 2. 最终功能范围

### 2.1 概念实验

学生输入：

- 物体重量。
- 完全浸没时排开水的重量。

系统输出：

- 上浮 / 悬浮 / 下沉。
- 水槽中的物体状态动画。
- 浮力和重力箭头对比。
- 面向学生的解释。

### 2.2 公式实验室

支持三类初中浮力公式：

- 阿基米德原理：`F浮 = ρ液 g V排`。
- 称重法：`F浮 = G物 - F示`。
- 漂浮平衡：漂浮时 `F浮 = G物`。

每次计算都展示公式、代入过程和结果。

### 2.3 真实题目训练

内置 10 道初中浮力题，覆盖：

- 判断浮沉。
- 称重法求浮力。
- 阿基米德公式。
- 漂浮平衡。
- 生活应用。

提交答案后显示正误、标准答案、分步解析和错因提示。

### 2.4 AI 小老师

AI 小老师支持：

- 答错后针对当前错误再讲一遍。
- 自由输入物理问题。
- 快捷追问按钮。
- SSE 流式输出。
- 无 key 自动降级。

Prompt 约束：只回答物理题目、物理概念、物理计算和物理实验现象相关内容。

## 3. 技术栈

| 层 | 技术 |
| --- | --- |
| 前端 | React + Vite + TypeScript |

## 5. 主要取舍

### 5.1 为什么不做完整课程

任务要求是「单一知识点科普小工具」。如果扩展成完整课程，会导致范围过大，四天内难以保证质量。

所以项目只围绕浮力，但把浮力拆成概念、公式和题目三层。

### 5.2 为什么不做复杂物理引擎

物理引擎会增加大量工程复杂度，但对讲清楚初中浮力不一定必要。

当前 demo 使用规则计算 + CSS 状态动画，能直观看到上浮、悬浮、下沉，足够支撑教学目标。

### 5.3 为什么题库先内置

Day1-Day4 的重点是可演示 MVP。题库内置能减少数据库设计、后台管理和部署复杂度。

后续如果继续做，可以接 PostgreSQL / Supabase 记录学生答题数据。

### 5.4 为什么 AI 不做通用聊天

通用聊天会让项目偏离「浮力学习工具」，也会增加不可控输出。

因此 AI 只做受限物理答疑，并且标准解析永远由系统题库提供，AI 只是补充讲解。

## 6. 当前风险

| 风险 | 当前处理 |
| --- | --- |
| AI 中转站不可用 | 自动降级为本地模板解释 |
| 学生乱问非物理问题 | Prompt 限制只回答物理学习相关内容 |
| 题库规模较小 | 当前先覆盖 10 道典型题，后续可扩展 |
| 线上域名/HTTPS 未配置 | 已提供 Docker 部署和反向代理说明 |

## 7. 后续迭代方向

- 增加错题记录和正确率统计。
- 让 AI 根据错因生成相似题。
- 增加教师端查看常错题。
- 增加更多液体密度和生活实验场景。
- 用 Supabase 保存题库和练习记录。

## 8. 面试讲述重点

可以按这个顺序讲：

1. 需求收敛：只讲浮力一个知识点。
2. 教学闭环：概念演示 → 公式计算 → 真实题训练 → 错因解释。
3. 工程闭环：API Contract → Pydantic 校验 → 前后端联调 → 测试 → Docker 部署。
4. AI 取舍：不做通用聊天，只做受限物理小老师。
5. 风险控制：无 key 降级、题库内置、标准解析不依赖 AI。
