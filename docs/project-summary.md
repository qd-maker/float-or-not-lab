# 浮不浮实验室最终项目总结

项目周期：Day1 到 Day7
在线 Demo：[https://float.heyqi.xyz/](https://float.heyqi.xyz/)

## 1. 项目一句话

一个面向小学高年级和初中生的浮力交互学习工具，通过概念实验、公式计算、真实题训练、动态错因、AI 讲解和同类强化，帮助学生从「看懂浮沉」走到「真正会做浮力题」。

## 2. 最终学习闭环

```text
看见浮沉现象
→ 理解浮力与重力的比较
→ 学会三种初中公式
→ 完成真实题目
→ 定位具体错因
→ AI 针对性讲解
→ 再练一道同类题
→ 查看学习进步与错题订正
```

## 3. 最终功能

### 3.1 概念实验

- 输入物体重量和完全浸没时排开水的重量。
- 判断上浮、悬浮或下沉。
- 水槽中的物体位置与计算结果联动。
- 浮力和重力箭头长度随数据变化。
- 区分「完全浸没时最大浮力」与「最终漂浮时浮力等于重力」。

### 3.2 公式实验室

支持三类初中常见方法：

- 阿基米德原理：`F浮 = ρ液 g V排`。
- 称重法：`F浮 = G物 - F示`。
- 漂浮平衡：`F浮 = G物`。

公式选择和输入项联动，每次计算显示公式、数字代入、结果和解释。`g` 限制为初中题常用的 `10 N/kg` 或更精确的 `9.8 N/kg`。

### 3.3 真实题训练

- 内置 10 道题，覆盖 5 类初中浮力题型。
- 支持选择题和数值填空题。
- 返回正误、标准答案、分步解析和动态错因。
- 常见错误由确定性规则识别，例如漏乘 `g`、漏乘液体密度、错误使用称重法和误解漂浮平衡。

### 3.4 学习记录与错题订正

- LocalStorage 保存逐题作答记录，不需要登录。
- 展示基础题完成进度、提交次数、正确率和待订正数量。
- 根据作答数据识别当前薄弱题型。
- 曾经答错的题自动进入错题本。
- 重新答对后自动标记为「已订正」。

### 3.5 AI 小老师

- 根据当前题干、选项、学生答案和标准解析进行针对性讲解。
- 允许学生继续输入物理问题，并提供动态快捷追问。
- 使用 SSE 流式输出长答案。
- 使用 Markdown + KaTeX 渲染数学公式。
- Prompt 只允许回答物理学习相关内容。
- AI 不可用时自动返回本地讲解，不阻断主流程。

### 3.6 针对性变式题

- 根据原题、学生答案和错因生成同知识点强化题。
- AI 输出先经过 Pydantic 和业务规则校验。
- 变式题使用确定性代码判题，不让模型决定正误。
- AI 异常、输出超纲或结构不合法时自动切换到本地题。
- 强化结果参与正确率和题型分析，但不改变 10 道基础题进度。

## 4. 技术架构

| 层 | 技术与职责 |
| --- | --- |
| 前端 | React + TypeScript + Vite，负责实验动画、公式交互、题目训练、学习记录和流式渲染 |
| 后端 | FastAPI + Pydantic，负责计算、题库、判题、AI 调用、结构校验和降级 |
| AI | OpenAI-compatible API，受限 Prompt、上下文注入和结构化输出 |
| 流式与公式 | Server-Sent Events + Markdown + KaTeX |
| 数据 | 内置题库 + LocalStorage，避免 MVP 阶段引入登录和数据库 |
| 部署 | Nginx + Uvicorn，仓库同时保留 Docker Compose 配置 |

当前不是完整 RAG 系统。AI 讲解通过当前题目的结构化上下文进行约束；若后续扩展大规模审核题库，再考虑向量检索和知识库。

## 5. 关键工程取舍

### 5.1 不使用复杂物理引擎

教学目标是讲清浮力与重力的比较，而不是模拟流体。规则计算和 CSS 状态动画更稳定，也更容易在七天内交付。

### 5.2 标准答案不依赖 AI

公式、基础题答案、动态错因和变式题判定都由确定性代码负责。AI 只负责换一种方式讲解和生成候选题目。

### 5.3 AI 功能必须可降级

没有 Key、中转站超时、JSON 解析失败或生成内容校验不通过时，系统会自动使用本地讲解或本地变式题。

### 5.4 MVP 不接数据库

当前没有账号和跨设备同步需求，LocalStorage 足够验证学习闭环。数据库被保留为下一阶段能力，而不是七日交付的前置条件。

## 6. 最终验证

- 线上首页和健康检查返回 HTTP 200。
- 前端生产构建通过。
- 后端 29 个测试通过。
- AI SSE、KaTeX、错题订正和变式题完成真实路径验证。
- 1440px、1024px 和 390px 布局完成浏览器检查。
- 390px 页面无横向溢出。
- `.env`、API Key、日志和构建产物未进入仓库。

## 7. 当前限制

- 题库只有 10 道审核过的基础题，尚未进行大规模内容管理。
- 学习记录只保存在当前浏览器，无法跨设备同步。
- Prompt 约束不能完全等同于模型安全边界，正式教育产品还需要输出审核和内容监控。
- 当前主要验证了功能闭环，尚缺真实学生的学习效果数据。

## 8. 下一阶段最有价值的方向

1. 邀请真实学生和老师完成可用性测试。
2. 接入 PostgreSQL 或 Supabase 保存账号、题库和学习记录。
3. 建立教师审核题库和题目版本管理。
4. 增加端到端测试、CI 和自动部署。
5. 用真实作答数据评估错因提示和强化题是否提高正确率。

## 9. 面试讲述重点

1. 为什么把范围收敛到浮力一个知识点。
2. 如何从简单计算器扩展成完整学习闭环。
3. 为什么标准解析和判题不能交给 AI。
4. 如何用 Pydantic、业务规则和本地降级控制生成内容。
5. AI 在物理概念、统计口径和前端布局上出过什么错。
6. 如何通过测试、浏览器验证和线上健康检查证明项目真的能运行。
